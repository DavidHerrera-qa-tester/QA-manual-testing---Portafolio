## 2. Project Overview
SauceDemo is a web-based e-commerce application used for practicing software testing.

The application allows users to log in, browse products, add products to a shopping cart, remove products from the cart, and complete a checkout process.

This project will simulate a real QA testing process for an e-commerce web application.

## 3. Objectives
The main objectives of this testing project are:

- Verify that the main e-commerce functionalities work as expected.
- Identify functional and usability defects.
- Validate positive and negative scenarios.
- Verify the checkout process.
- Document defects using professional bug reports.
- Perform exploratory testing.
- Perform regression testing after defect resolution.
- Generate a final test summary report.

## 4. Scope
The testing scope includes the main user flows available in the SauceDemo application.

### 4.1 In Scope
The following functionalities will be tested:

- User Login
- User Logout
- Product listing
- Product details
- Product sorting
- Shopping cart
- Adding products to the cart
- Removing products from the cart
- Checkout process
- Checkout form validations
- Order summary
- Navigation
- Basic responsive behavior
- UI consistency

### 4.2 Out of Scope
The following areas are outside the scope of this project:

- Payment gateway integration
- Real financial transactions
- Backend implementation
- Database testing
- Load testing
- Performance testing
- Security penetration testing
- API testing
- Automated testing

## 5. Testing Types
The following testing types will be performed:

- Exploratory Testing

## 7. Test Data
The following test data will be used during functional testing:

- Valid user credentials provided by the application.
- Invalid username and password combinations.
- Empty fields.
- Valid checkout information.
- Empty checkout fields.
- Invalid or unexpected input values where applicable.

Sensitive personal or financial information will not be used.

## 8. Entry Criteria
Testing can begin when:

- The application is accessible.
- The testing environment is available.
- Test data is available.
- The main application functionalities are accessible.
- Test cases have been prepared.

## 9. Exit Criteria
Testing will be considered complete when:

- All planned test cases have been executed.
- Critical and high-priority defects have been documented.
- Failed test cases have been analyzed.
- Regression testing has been performed where applicable.
- Test results have been documented.
- The final Test Summary Report has been completed.

## 10. Risks
Potential risks include:

- Application availability issues.
- Browser compatibility issues.
- Unexpected application behavior.
- Insufficient test data.
- Defects that prevent execution of subsequent test cases.
- Limited testing time.

## 11. Deliverables
The following QA deliverables will be produced:

- Test Plan
- Test Cases
- Test Execution Results
- Bug Reports
- Exploratory Testing Notes
- Regression Testing Results
- Test Evidence
- Test Summary Report

## 12. Defect Management
Defects identified during testing will be documented using individual bug reports.

Each defect report will include:

- Bug ID
- Summary
- Environment
- Preconditions
- Steps to Reproduce
- Expected Result
- Actual Result
- Severity
- Priority
- Evidence
- Status

## 13. Test Execution
Test cases will be executed manually according to the approved test scenarios.

Each test case will be assigned one of the following statuses:

- PASS
- FAIL
- BLOCKED
- NOT EXECUTED

The final execution results will be documented in the Test Execution report.
